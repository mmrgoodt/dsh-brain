# 架构

这份文档讲三件事：一轮对话进来之后数据怎么流、每个模块负责哪一段、库里存了什么。

## 数据流

```
用户说一句话
   │
   ├─ recordEvent()          事件层：原文先落 events（不筛选，留着回溯）
   │
   └─ ingestTurn()           写入层
        ├─ 三道闸             过程话？没新增？分不出类别？
        ├─ splitSentences()   一句话里塞了几条记忆就切几条
        ├─ writeImpression()  主写入管线
        │    ├─ 质量闸        太短 / 纯符号 / 同字重复 → 拒
        │    ├─ findSimilar() 高度相似 → 只给旧条加分，不新建
        │    ├─ findConflict() 同主题且取值不同 → 旧条 superseded
        │    ├─ 关系转接       旧条身上的 bonds / causes 改挂到新条
        │    ├─ 建边          同在 / 重复
        │    └─ addCause()    因果（带证据、成环检测、时间倒挂降级）
        └─ 向量化             embed.js 写 vectors
```

检索与注入在每一轮对话开始时发生：

```
buildInjection()
   ├─ recall()        点火 → 一跳扩散 → 重排 → 取前 N
   ├─ blockNow()      现在：时间锚、目标、卡点、刚说到的话
   ├─ blockMemories() 我记得：带保留语气的记忆条目
   ├─ blockVoice()    说话风格
   └─ 按预算裁剪后拼成注入文本
```

## 库里的表

| 表 | 存什么 |
| --- | --- |
| `events` | 每一轮对话的原文（不筛选，供回溯） |
| `impressions` | 记忆条目：正文、类别、确信度、权重、用过几次、等级、项目、来源 |
| `bonds` | 关系边：`a → b`，类型 `co` / `repeat`，带权重和「为什么连」 |
| `causes` | 因果边：`cause → effect`，带证据、确信度、状态 |
| `scenes` | 场景：一段连续对话的主题、成员 |
| `vectors` | 向量：每条记忆的嵌入 |
| `imp_fts` | 全文索引：中文按二元组切 |
| `focus` | 现状：目标、已定、卡点、下一步 |
| `meta` | 元信息：schema 版本等 |
| `backups` | 备份记录 |

## 几个关键取舍

**为什么事件和记忆分两层。**
`events` 存原文，`impressions` 存提炼过的记忆。筛选错了还能从事件层重新提炼；只存记忆就再也回不去了。

**为什么关系要单独存表，而不是每次现算。**
现算意味着每次检索都要两两比较，条数一多就废了。边是写入时建的，检索时只做图遍历。

**为什么覆盖时要转接关系边。**
旧记忆被新说法取代后，如果边留在旧条目上，读到「为什么 X」的时候链路会停在一个已作废的节点上。转接让链路保持连续，同时旧条目仍以 `superseded` 状态留着备查。

**为什么扩散只走一跳。**
两跳会把「朋友的朋友」拉进来，语义漂移明显。实测走两跳之后，召回结果的噪声大到没法用。

**为什么 `level` 要参与打分。**
`level` 本来只是标签（`clear` / `blur` / `sunk`）。当它不参与排序时，「降级」等于没降——旧记忆照样能挤掉新的。现在它按档位乘系数：`sunk` 0.35、`blur` 0.7。
